# Phase 2, Task 5: final validation and acceptance report

Date: 2026-11-12. Branch `feat/phase-2-dob-311`; the last code commit is `3e58491`.
This report changes no code, migration, fixture, recording, digest, mapping or attribution
rule.

## 1. Executive summary

Task 5 adds DOB complaints, DOB ECB violations and 311 service requests to the records
layer, with building attribution and PostgreSQL persistence. The implementation,
PostgreSQL integration and automated tests were accepted earlier. The ECB legacy-snapshot
fix (`3e58491`) was approved and closed on 2026-11-12.

Manual validation followed the approved reduced, risk-based plan:

| Source | Manually checked |
|---|---|
| DOB | 16 of 91 checklist complaints; 75 not individually checked |
| OATH | the 2 required summons lookups |
| HPD Online | 3 building sessions, covering Overview, Violations and Complaints |

The manual checks found no attribution error and no implementation error. All seven
acceptance criteria are satisfied within that scope (section 2).

Several disagreements between and within agency sources remain open and are listed in
section 7. The sample was chosen for risk and is not statistically representative, so no
population error rate is derived.

**Recommendation.** Accept Task 5 for research and portfolio prototype use, with the
limitations in section 8. It is not a comprehensive or certified building-history audit,
and it is not fit for real-estate due diligence. Formal closure needs the project owner's
approval.

## 2. Acceptance criteria

These are the seven criteria of the approved revised validation plan (research
prototype).

### Criterion 1. Resolver benchmark: 0 wrong-building automatic matches

- **Evidence:** CI run 40780318102: benchmark 14/14 with 0 wrong-building matches.
- **Satisfied:** yes.
- **Limitations:** 14 benchmark addresses. This is not a citywide accuracy measure.

### Criterion 2. Every manually checked record matches the agency on identity and building

Any attribution error stops acceptance until it is fixed with approval.

- **Evidence:**
  - DOB: 16/16 complaints match BIS on identity, BIN and building attribution.
  - HPD: 3/3 buildings match on HPD building ID, BIN and block/lot. All 14 sampled HPD IDs
    present in the recording are on the building HPD Online shows them under (section 4).
  - OATH: both summonses match on property address.
- **Satisfied:** yes. No attribution error was found.
- **Limitations:**
  - OATH shows no BIN or BBL, so the building attribution of 035122802P is consistent but
    not independently established.
  - The DOB checks are a risk-selected 16 of 91.

### Criterion 3. Automated cross-checks are reproducible, and their disagreements are counted and shown

- **Evidence:**
  - Parts C, D and E under `docs/task5/validation/` are generated by committed scripts and
    pinned by tests.
  - Part D covers all 312 recorded summonses: 223 matched and 89 not found in the dataset.
  - Part C keeps all 91 checklist complaints.
- **Satisfied:** yes.
- **Limitations:** the cross-checks compare against open datasets that are themselves
  incomplete (section 7).

### Criterion 4. No output claims more than the evidence

The rules: order status is never inferred; stipulations, admissions, cures and defaults are
not called hearing decisions; uncertain rows are labelled.

- **Evidence:**
  - Enforced in code and tests by the approved adjudication revision (`0127027`) and the
    legacy loader (`3e58491`).
  - Manual results are consistent with it: current order enforceability stays
    INCONCLUSIVE for every checked order, and 035122802P is recorded as a stipulation, not
    a contested decision.
- **Satisfied:** yes.
- **Limitations:** several DOB and OATH outcome codes have no documented meaning (section 7).

### Criterion 5. Privacy

Privacy tests pass, and no 311 unique key, unit, complainant or respondent data appears in
public output.

- **Evidence:**
  - The privacy tests are green in CI run 40780318102.
  - This report and the manual evidence notes contain no apartment identifiers, names,
    condition descriptions or 311 request numbers.
- **Satisfied:** yes.
- **Limitations:** none known.

### Criterion 6. The minimal OATH and HPD A/B checks are recorded, with every difference classified

- **Evidence:**
  - OATH: 2/2 required lookups recorded (section 3.2).
  - HPD: 3/3 sessions recorded. Every HPD difference is classified as snapshot, source
    timing or definition; none as an implementation error (section 4).
  - The absence of 038059001P from the OATH dataset is classified "cause not established".
- **Satisfied:** yes, under the reduced scope.
- **Limitations:**
  - 3 of the 5 originally listed OATH summonses were not individually checked.
  - The optional blank-ADMIT lookup was not done.
  - HPD violation statuses for the sampled IDs were not reported.

### Criterion 7. The report states the scope

The required statement is that 16 of 91 DOB rows were checked by hand, chosen for risk,
and 75 are NOT INDIVIDUALLY VERIFIED.

- **Evidence:** sections 1, 3 and 8 of this report.
- **Satisfied:** yes.
- **Limitations:** no error rate is derived from the sample.

## 8. Limitations

- **Sample.** The manual sample was chosen for risk: active complaints, orders,
  cross-building and condo cases. It supports no error rate and no statistical claim. The
  hash-ordered closed sample in Part C stays available for a later random check.
- **Snapshots.** Records are snapshots from 21 to 23 Oct 2026, and agency data changes
  daily, so current figures will differ.
- **HPD scope.** HPD Online shows only the last two years. All-time HPD counts and the
  sampled violation statuses were not independently verified.
- **Evidence form.** Manual evidence is a text transcription. No screenshots are archived.
- **Historical coverage.** The OATH open dataset is incomplete for older summonses. ECB
  attribution is confirmed at lot level, not BIN level.
- **Layer covered.** Validation covers the records layer only. The agent (LangGraph),
  report generation and frontend have not been built or validated.

## 9. Recommendation

Task 5 is **recommended for acceptance for research and portfolio prototype use**, within
the reduced manual scope and the limitations above. All seven acceptance criteria are
satisfied. No attribution or implementation error was found, and every open disagreement
is documented rather than resolved by assumption.

It should not be described as exhaustively verified, certified, or a complete building
history.

Formal closure of Task 5, any freezing of ground-truth rows, and the start of Phase 3
each require the project owner's approval.
